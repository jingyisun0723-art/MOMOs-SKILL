# MOMO’s SKILL

## 01 · TIMING

`timing` 是 Codex 自主工作的启动口令。先定交付、时限和额度，一句话确认后，Codex 按约定自行推进。

```text
你            timing 检查这份 PDF 的页数、方向和空白页，列出异常
MOMO｜待确认   给出检查结果和异常页码。建议 60 分钟，预留 20% 额度。
你            30 分钟，留 25%，开工
MOMO｜执行中   30 分钟 · 预留 25% · 验收时列出已检查的文件和异常页码
```

`MOMO，状态` 查看已完成、已验证和剩余时间。`MOMO，收工` 停止发起新操作并交代续做点。

### 使用

在本仓库打开新的 Codex 会话，可以使用 `.agents/skills/momo-timing`。如果希望在多个项目里用，把整个 `momo-timing` 文件夹放到个人 `.agents/skills` 目录。若当前客户端没有自动识别口令，先用技能选择器加载 **MOMO Timing**，再单独发送 `timing 任务内容`。

额度为账户共享的剩余百分比。截止时间和预留额度在实际可检查的节点核对，已开始的外部进程能否停止取决于该进程。可读取额度的能力取决于当前客户端。未来提醒和周期检查使用当前客户端提供的定时功能。

### 验证

Python 3.11+ 可运行随附检查脚本与单元测试，Skill 的对话流程本身也可独立使用。

```shell
python -m unittest discover -s tests -v
```

还可以用下面几个对话复测行为：

| 输入或场景 | 预期行为 |
| --- | --- |
| `能解释一下 timing 吗？` 或引用 `` `timing` `` | 正常回答，无待确认任务 |
| `timing 整理这份资料` | 发出一张待确认卡，授权前没有任务写入或调度 |
| 待确认时回复 `90 分钟` | 更新提议，继续等待明确确认 |
| 待确认时回复 `90 分钟，留 25%，开工` | 使用新参数立即开始，回执显示实际截止时间 |
| 每周额度到预留线，5 小时额度充足 | 保存已验证结果和续做点 |
| 一次打包与每周检查 | 打包在当前对话跟到结果。周期检查在明确确认后调度 |
| 等待确认时再次输入 `timing 另一个任务` | 说明当前待确认任务。先确认是否替换 |
| 要求必须能核实预留额度，当前没有读数 | 留在待确认状态，说明缺少的读数 |
| `0 分钟，留 110%，开工` | 请求修正参数，保持待确认 |

## 02 · DRAWING

[DRAWING](.agents/skills/momo-drawing/SKILL.md) 用于三线建设与工业遗产研究制图。它串起组会意见、微观资料与历史影像、QGIS 地理校核、Illustrator 分层排版，以及 AI、PDF 和 PPT 的交付检查。

- **地图与图册**：宏观分布、中观厂村关系、微观厂区与双时相对照。含京津冀蓝灰地形色卡、横竖版和原范围／扩大范围，以及两种高程置顶图例。
- **论文配图**：按研究问题组织统计组图与机制图，保留图源和计算口径。

在本仓库的 Codex 会话中选择 **DRAWING**，或调用 `$momo-drawing`。跨项目使用时，将 `.agents/skills/momo-drawing` 整个目录放入个人技能目录。

```text
用 $momo-drawing 对照最新版微观图和组会意见，修订三线图册的中观厂界、道路和水系，先检查竖版样页，再出横竖两种范围。
```
